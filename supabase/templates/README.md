# TideTrace authentication emails

These two HTML templates reuse the reference email's navy header, rounded white card, small category badge, details panel, action button, fallback link and footer. They use TideTrace's existing colors, wave mark, wordmark and “Every ripple counts.” tagline. Both templates include an optional code block and a greeting that falls back to “Hello,” when the display name is absent.

## Install with Supabase and Brevo SMTP

TideTrace currently uses Supabase Auth. **Paste these files into Supabase's email templates.** Supabase supplies the links and codes, renders the HTML and hands the completed email to Brevo SMTP. Saving a template in Brevo does not change the email generated by Supabase.

| File | Supabase template | Suggested subject |
| --- | --- | --- |
| `confirm-signup.html` | Confirm signup | Confirm your email for TideTrace |
| `reset-password.html` | Reset password | Reset your TideTrace password |

1. Deploy the frontend, including `client/public/email/tidetrace-wave.png`. Vite serves this file at `/email/tidetrace-wave.png`. It is a 96 × 96 transparent PNG rendition of the existing wave icon, with a white stroke for the navy header; it displays at 32 × 32. Using a PNG avoids reliance on SVG support in email clients. The TideTrace wordmark remains ordinary text even when remote images are blocked.
2. In Supabase **Authentication → URL Configuration**, set **Site URL** to the frontend origin, with no trailing slash. Use the deployed HTTPS origin for production, and allow its `/auth/callback` redirect. For local development the existing allowed URLs are `http://localhost:5173/auth/callback` and `http://127.0.0.1:5173/auth/callback`.
3. Under **Authentication → Emails → SMTP Settings**, enable custom SMTP and configure your verified Brevo sender, `smtp-relay.brevo.com`, port `587`, Brevo SMTP login and SMTP key.
4. Under **Authentication → Emails → Templates**, select each template from the table above, set the subject, and replace the body with the **entire contents** of its HTML file. Save each one separately. Keep email confirmation enabled if signup must require verification.
5. Disable link tracking for these authentication emails in Brevo so verification URLs are not rewritten.
6. Test signup with an address you control, then test password recovery for that account. Check the button, code and copy/paste link, and inspect mobile and desktop inboxes. Confirm that an account without a display name still receives a sensible greeting. Use a fresh message for each verification attempt: links and codes can expire or be consumed by a previous attempt.

The files are paste-ready Supabase templates. They do not apply hosted settings or send emails by themselves. No database migration, backend change or new SMTP package is required.

## Variables and assets

| Placeholder | Supplied by |
| --- | --- |
| `{{ .ConfirmationURL }}` | Supabase; used in the button and fallback link |
| `{{ .Token }}` | Supabase; shown when a token is available |
| `{{ .Email }}` | Supabase; the account email |
| `{{ .Data.display_name }}` | Supabase Auth user metadata; TideTrace supplies it at signup |
| `{{ .SiteURL }}` | Supabase Site URL; used for the wave image URL |

The logo URL must be reachable from the recipient's email client. A localhost Site URL works for local app redirects but cannot reliably deliver the logo to an email client. For testing before deploying the frontend, replace **only the image's `src`** with an HTTPS URL for a copy of the included PNG uploaded to your own hosting or Brevo image library. Do not replace the confirmation link with your site's login or forgot-password page.

The HTML uses presentation tables, inline styles, a 600px maximum card width, system-font fallbacks and mobile spacing rules. Rounded corners and other decorative details may vary by email client. Outlook desktop receives a fixed-width table wrapper; the main content is readable without media-query support. No JavaScript, external fonts, tracking pixels, device details or IP addresses are included. The token display has no fixed digit count, so it accommodates the app's supported code lengths. Expiration copy intentionally does not assume a fixed project setting.

## If you later send directly with Brevo's template API

Brevo's HTML editor can import this layout, but it does **not** interpret Supabase's Go template syntax. For direct API sending, create separate versions with Brevo placeholders (for example `{{ params.confirmation_url }}`), replace the conditional greeting/code blocks with Brevo-compatible content, use an absolute HTTPS logo URL, and provide every required value from a trusted backend. An API key for that approach is different from the SMTP key used by Supabase. Direct API sending is not required for TideTrace's current signup and recovery flows.
